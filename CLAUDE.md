# ECUStudio: правила работы

Архитектура и инварианты: [ARCHITECTURE.md](ARCHITECTURE.md). Запуск: [README.md](README.md).

## Обязательно в начале каждого пакета доработок: короткий QA

Перед изменениями быстро проверить уже работающее приложение. Это не аудит, на него не тратится много времени.

1. Запустить backend и frontend (`dotnet run --project src/ECUStudio.Api` после `npm run export:desktop`).
2. Пройти основные страницы (Dashboard, Vehicle, ECU, Binary, Maps, Diff, Simulation, Risks, Logs).
3. Проверить console, network и логи backend.
4. Найти очевидное: ошибки frontend и runtime, сломанные вызовы API, неправильные состояния, логические ошибки,
   регрессии, недоделанные элементы.
5. Исправить критичное, что связано с текущим пакетом.
6. Сразу перейти к основной разработке.

## Инварианты, которые нельзя нарушать

* Оценки всегда с диапазоном и confidence. Неизвестный предел: `UNKNOWN`, никогда `SAFE`.
* Бинарь не портится: размер, offsets и padding не меняются; правки только через patch-модель; сохранение в новый файл.
* Деталь не придумывается по одному VIN: у каждого вывода есть source, confidence и evidence.
* Слабая гипотеза не показывается как название карты.
* AI работает только со структурированным контекстом и ссылается на evidence.

## Проверки перед push

`dotnet test`, `cd frontend && npm run typecheck && npm run build`.
